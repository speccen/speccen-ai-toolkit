Search work on the cheap tier, fewer verifier runs

speccen sends search work to the model tier of each phase. The main session keeps every decision. The gate test fixes common record errors before the verifier runs, and a second verifier run checks only the affected rows.

What is being built

speccen already has model tiers. A phase sets phases.<phase>.model to economy, balanced or premium. In the evidence bundle, 13 subagents ran, and all 13 ran on the session model.

Two causes exist. First, searching is not a listed unit, so no tier applies to it. Second, the gate verifier runs too often, and its second run checks every row again.

This change does two things:

  • Change A — search becomes a unit. A search finds and quotes evidence for one question. It runs on speccen-worker on the phase tier. It returns findings only.
  • Change B — fewer verifier runs. The main session runs five self-checks before the verifier. A second verifier run checks only failed rows and rows whose evidence file changed.

Source: the Architect's brief (issue #22) and the Phase 01 analysis.

How a search runs (L3)

  1. A phase step needs evidence for one question.
  2. The main session writes a work order: the question, the breadth, the start place, and Outputs: none — report only.
  3. The main session resolves the tier from the phase's model. With no model key, the search runs on the session model.
  4. The main session launches speccen-worker with that model. If the host cannot launch it, the search runs inline and the session says so once.
  5. The worker returns findings: path:line, a short verbatim quote, and what it did not find. It writes no file.
  6. The main session opens each finding again before it cites the finding.

How the gate test runs (L3)

The five self-checks are:

  1. Quotes — every quote of the Architect matches log.md word for word.
  2. References — every path:line and anchor still points at what the row says.
  3. Latest answer — no record is behind the newest Architect statement in log.md.
  4. Index — index.md lists every file the phase wrote.
  5. Interview structure — every round holds only the frontier, and every question holds one decision.

Requirements and acceptance scenarios

R-1 — Search is a listed unit

The governing skill SHALL list a search as a subagent unit: code in Phases 02–05, bundle and store in any phase.

  • WHEN a phase needs evidence for one question
  • THEN the Units table names a search unit for that phase and source.

R-2 — Findings only

A search SHALL return findings only — path:line, verbatim quote, what was not found — and SHALL write no file.

  • WHEN a search unit returns
  • THEN its report has no conclusion, and no file was written.

R-3 — Re-open before citing

The main session SHALL open every finding again before it cites the finding, and SHALL never cite a search report alone.

  • WHEN a finding is cited in a phase file
  • THEN the citation points at the code, not at the report.

R-4 — Worker and tier

A search SHALL run on speccen-worker with the phase's model tier. With no model key, it SHALL run on the session model.

  • WHEN Phase 02 searches with model: economy
  • THEN the worker starts with the economy model.
  • WHEN Phase 01 searches the store
  • THEN the search runs on the session model.

R-5 — Inline fallback

A search that is not launched as the unit SHALL run inline.

  • WHEN the host cannot launch the worker
  • THEN the search runs inline on the session model, and the session says so once.

R-6 — model on 04 and 05

model SHALL be a valid key on specification and implementation.

  • WHEN a project file sets phases.implementation.model: economy
  • THEN the workflow uses it.
  • WHEN a project file sets phases.feature-analysis.model
  • THEN the workflow ignores it and says so once.

R-7 — Template version 2

The template SHALL be version: 2, with model: economy on specification and implementation.

  • WHEN a new project file is written
  • THEN it has version: 2 and both keys.

R-8 — Upgrade keeps behaviour

The upgrade of an existing project file SHALL keep its effective settings.

  • WHEN a version-1 file is upgraded
  • THEN it gets model: inherit on 04 and 05 and version: 2, and no setting changes.

R-9 — Pointers

Phase skills 02, 05 and interview SHALL point to the search unit.

  • WHEN a reader is at 02 Steps 2 and 3, 05 Step 3 or the interview lookup rule
  • THEN one line points to Subagent Execution → Search.

R-10 — Self-check

The gate test SHALL run the five self-checks before the verifier and record them.

  • WHEN a phase gate test starts
  • THEN the summary shows Self-check: done — N fixes above the gate table.

R-11 — Delta re-check

A second verifier run SHALL check only failed rows and rows whose evidence file changed. The workflow SHALL stop if a re-checked row still fails.

  • WHEN run 1 fails one row and the fix edits one file
  • THEN run 2 checks that row and the rows that cite that file; other rows show confirmed (run 1).
  • WHEN a re-checked row still fails
  • THEN the workflow stops (a stop).

R-12 — Verifier stays on the session model

The verifier and every decision seat SHALL stay on the session model.

  • WHEN any tier mapping is set
  • THEN the verifier still runs on the session model.

R-13 — Copies match

Restated copies SHALL match their source.

  • WHEN the change lands
  • THEN the README template equals the governing template, and ARCHITECTURE, README tiers and the worker description name the search.

R-14 — Logged like any unit

Each launched search SHALL be logged with the existing subagent line, with the tier and the model.

  • WHEN a search unit is launched
  • THEN log.md gets - **HH:MM — [PHASE] subagent** — search: <question> · model: <tier> → <model> (<source>), and the log format stays the same.

R-15 — Work order and parallel searches

A search work order SHALL state the question, the breadth (quick · medium · thorough) and the start place if known. Independent searches MAY run in parallel.

  • WHEN two searches answer independent questions
  • THEN both may run at once, each with its own work order.

R-16 — No host-wide default

The change SHALL NOT add a host-wide default subagent model.

  • WHEN the change lands
  • THEN the only model settings are phases.<phase>.model and models.<tier>.
