# ADR 2026-11-12 — Fix budget default: 1 or 5 fix attempts

<a id="decision"></a>

|     | Info |
| --- | --- |
| **Subject** | Fix budget default: 1 or 5 fix attempts |
| **Status** | DECIDED |
| **Context** | The specification set the default of `fixes` to `1` so that a project keeps today's behaviour (R-2; brief §3; DD-17, delegated). The review raised the ceiling to 10 ([ADR 2026-11-11](./2026-11-11.fix_budget_ceiling_10.md)) but left the default and the specification as they were. After close-out, the Architect noted that the specification must steer the implementation and set a new default. |
| **Decision** | "the max cap is raised to 10, and the default value should be 5" — the Architect (2026-11-12). Answers to the follow-up questions: absence of `fixes`, the template and the version-3 upgrade all mean `5` ("5 everywhere"); a value that is not a whole number from `1` to `10` still counts as `1` ("Counts as 1"). DD-17 is OVERRIDDEN. |

<a id="consequences"></a>

| Consequences |
| --- |
| An autonomous project that upgrades to version 3 makes up to five fix attempts per gate test; the upgrade sentence tells the Architect to set `fixes: 1` to keep one. The upgrade still writes the value its absence means, so R-12's "keep every effective setting" holds against the new default. The progress and conclusions guards bound every loop. |
