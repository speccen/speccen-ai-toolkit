# A gate test makes no progress when a breach comes back or more rows fail — not when fewer rows fail

[Index](../index.md)

---

|     | Info |
| --- | --- |
| **What** | "Is 'no progress' measured by breaches, not by the count of failed rows?" → yes (delegate, Phase 03 interview 03/5, DD-14); adopted by the Architect: "rest yes" (review R/2, 2026-11-11). |
| **Why** | A later verifier run re-checks a different set of rows, so a row count does not compare two runs. In this bundle, Phase 02 check runs 4 and 5 each failed one row on a different defect, and run 6 passed; the brief's "fewer rows" would have stopped that converging run. |
| **Alternatives** | Stop when a run fails as many rows as the run before (the issue #25 brief, §2 guard 1) — not chosen. |
